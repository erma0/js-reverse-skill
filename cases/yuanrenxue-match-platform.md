# 猿人学 match 平台共性（match.yuanrenxue.cn）

> **平台级通用知识**，由 match4~29 多题实测沉淀（每条标注实证题号）。刷任何 match 题先读本篇，
> 再按 `cases/yuanrenxue-match-index.md` 题号速查定位该题案例。
> 本篇内容是**基线假设**，不是免取证通行证——各题风控配置独立，迁移任何步骤前先直接请求一次
> 数据接口验证是否必要（反模式 18）。题号案例文件只保留**本题差异与专属事实**，不重复本篇。

## 1. 请求与提交链路

- 数据接口现行为 `GET /api/question/N?page=N&pageSize=10&kw=`（老题解的 `/api/match/N` 已迁移，
  JS 内可能保留老常量由页面 hook 改写；**接口路径一律以本次抓包为准**，match16 实证）。
  也有例外路径形态（match18 `api/v/question/18data`、match10 `api2/10`）——诱饵接口多，
  首轮取证用脚本输出的「动态 2xx 接口候选」校准 `--targets`（match18 实证）。
- 通关提交：`POST /a/N` 表单编码（`application/x-www-form-urlencoded`）`{answer}`；
  返回 `code=2` 通关、`code=1` 重复提交、`exp` 为分值。禁止猜 JSON 提交（SKILL.md §10 写请求格式取证）。
- 未登录 sessionid 通常也能拉数据（200），但**提交需要活会话**：换会话先 `GET /api/user`
  验活 `isLogin:true` 再提交（match26/28 实证；数据接口不校验登录不代表提交接口不校验）。
- **数据绑定 sessionid**：同 sessionid 数据恒定可复验；**换 sessionid 数据完全不同**，
  答案必须按提交所用会话重算（match9/10/14/28/29 实证，反模式 19 session 基线）。

## 2. 末页 UA 校验

- 绝大多数题末页（page5）要求 `User-Agent: yuanrenxue`；普通 UA 返回 **HTTP 200 + 中文提示数组**
  （按 `data` 元素类型判别，不是 4xx 状态码；match12/15/16/17/19 等多题实证）。
- 已知差异：match18 需 `page=05`（VM 不签 page 字面值 1/5，末页 UA + page=05 双重校验）；
  match14 改 UA 时**指纹数组 UA 字段必须同步**（否则 mz↔m 不自洽 400）；内容还原题
  （match4/7）按各自案例为准。

## 3. 服务器时间源

- `GET /api/getTime` 返回**纯文本服务器毫秒**，每次翻页/签名前重新取（now 注入，match29 实证
  每次翻页前注入新值）；token 材料含服务器时间时，token 与配套头（如 match21 `accept-time`）
  必须**同源同值**（浏览器双轨时间源错位 → 浏览器自身 400）。
- 时间窗口判读：先做 T 偏移矩阵量边界再动手（match25 实证 now±100s 全过 → 冻结 Date=getTime
  值最稳，无需补偿；match24 实证 2~4s 窗口 → 按页构建即时请求）。

## 4. 诱饵参数惯例（反模式 27）

- 页面普遍埋 `m:window.matchN` / `window.matchnumber` 类诱饵参数：值恒 `undefined`，
  被 `$.param`（渲染空串）或 `$.ajax` 深拷贝 `copy!==undefined` 守卫（match19 修正机理）丢弃，
  **真实请求中不存在**——参数名存在 ≠ 参数生效，不要去逆（match7/13/17/18/19/27/29 多题实证）。

## 5. 风控底座

- **蜜月期**（match4/5/6 同源底座）：开窗 GET HTML 约 5 秒、成功请求续期；签名正确时无页间隔
  要求（无缝连发全过）；**「放慢速度」类文案实为签名错误信号**，签名确认正确前不得按字面归因
  频率；失败 5-10 次进惩罚期（冷却 10 分钟+，惩罚期内基线失败、对照数据全部作废）。
- **限流**（match27/28）：短窗口连续数据请求约第 3 页起 403 `token failed` / 429，**单请求正常、
  第 1/2 页正常——不是签名错**。先做单请求诊断（fresh now+token 单发 page=1，200 即签名对），
  再放慢节奏：页间 3s + getTime 后 300ms + 冷却 3~4 分钟（惩罚恢复期长勿连跑）；
  **采集与提交解耦**（算好答案后单独单请求提交）。
- **`token failed` 文案多义，不指示病因层**：m-cookie 缺失（match9）/ Node TLS 指纹黑名单
  （match19）/ 算法环境分支错误（match21/26 诱饵分支）/ 站点限流（match28）。先按 SKILL.md §10
  双对照分层定位，禁止按文案直接归因。
- **各题风控配置独立，禁止照搬**：match7 无蜜月期且**勿开窗**（开窗 HTML 响应 Set-Cookie 重置
  登录 sessionid → 提交 401）；match10 每页都要 m（与 match9 验证后免 m 不同）且页面加载时重置
  sessionid；match21 无 TLS 拦（与 match19 相反，curl_cffi 也被拒时先排查 token 内容）。
- TLS 客户端按题而异：Node 原生 https 多数题可用；match19 Node 全 400（黑名单→切 Python
  requests）；match22/24 TLS 白名单（curl_cffi / 桥式交付）。以三客户端阶梯对照实测为准（规则 27）。

## 6. 取证注意

- 翻页/序列类取证交互覆盖 **≥2 个请求序号**（单序号看不见计数器递增语义，反模式 24，
  match14 实证）。
- 每轮取证会轮转 `capture.json`/`document.html` 等同名产物为 `.prev-1~3`；跨轮关键样本
  及时转录固化（match21 实证：轮转吃掉正在分析的产物）。
- 取证浏览器（Firefox 内核）对部分题**必 403**（内核走诱饵分支，match21/26）：target-hits.json 的
  URL/参数结构仍是有效证据，勿无限重采；签名正确性交给 trace 定位 + 沙箱对齐 + REAL_VERIFY 闭环。
- 题面「试炼步骤」区块为**唯一口径来源**（求和范围、页数、提交方式），勿按惯性假设 3 页
  （match20 实证）。

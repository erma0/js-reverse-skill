# VMP 反编译：黑盒之后的例外路径

**默认路线不变**：JSVMP 一律黑盒执行或最小环境复现（SKILL.md 边界；识别路由见 §7）。进入本路径前必须已穷尽：

1. **RuyiTrace eval 落盘**（规则 39/反模式 37）——vmpzl 系 VM 业务层经 eval 执行反序列化源码，`case/ruyi-trace/logs/eval/eval_*_eval-direct.js` 落盘即业务逻辑，**多数"VMP 题"到这一步就已结束**；
2. 字节码尾部大数字面量扫描转纯算（match28，规则 35）；
3. 带栈 opcode 黑盒执行 + 语义级对齐（match18/24/25）。

**本路径触发条件（三条同时满足）**：① 纯 Web JS VMP（无 .so、无 Native，如腾讯 tdc、快手 sig3 类）；② 黑盒多轮仍无法产出与真机一致的输出，或必须理解算法内部逻辑（分支语义、密钥编排）而非仅出值；③ 用户明确接受更高时间成本。

严禁用于 App / 小程序 Native / 加壳部分（绝对规则 4）。

## 方法（腾讯 CHAOS_VM 类结构实证）

VMP 反编译的核心 = **理解 VM 如何运行，再按运行流程把指令流重建成 AST**。

1. **认清调度核**：`Q[m[g++]]()` —— `Q` = 指令集函数数组，`m` = 字节码数组，`g` = 程序计数器；主循环 `B = Q[m[g++]]()` 遇返回 true 的指令（如 jump-not-taken）出内层循环。
2. **先跑起来**：文件头补 `window = {}` 直接 Node 运行；VM 自执行函数通常接收 `(pc, bytecode, constPool, locals, env, …)`。
3. **插桩记录指令序列**：在 `Q[m[g++]]` 处打印 `g` 与索引，得到真实执行轨迹——后续按序重写指令，而不是按数组顺序。
4. **逐条重写指令语义**（栈机语义，`n` 为操作数栈）：压栈/出栈、二元运算（`n[len-2] = n[len-2] OP n.pop()`）、取成员（`A[0][A[1]]` 双元素帧）、调用（slice(-A) 收参 → pop this → apply）、**闭包创建指令**（捕获 `p[]` 上值槽 + `A[0]=[this], A[1]=[arguments], A[2]=[w]` 自引用 + `Q[C]` 参数槽位映射 → 返回重新进入 VM 的函数 `w`）——函数节点是还原难点，需单独建模为 AST 的 FunctionDeclaration/FunctionExpression。
5. **异常表还原**：`C.push([catchPc, stackLen, slot])` 结构即 try/catch 元数据——出栈恢复 `g = o[0]; n.length = o[1]; n[o[2]][0] = K`。
6. **重建 AST 生成源码**，与真机输出逐值对拍。

工具偏好：重写指令时用**改写原 JS + 打印**的方式做对照（保留原语义），比凭空重建解释器快得多；AST 生成复用 `assets/ast-patterns` 的 babel 基建。

## 纪律

- **时间盒**：反编译成本数倍于黑盒，预算耗尽即回退黑盒 + 分支对齐路线，不强求"读懂"。
- **对拍验收**：反编译产物必须与真机同输入输出一致才算还原成功；不一致时优先怀疑指令语义重写错误，其次环境分支。
- **产出沉淀**：同族 VM（同一混淆厂商）指令集高度相似，还原出的指令语义表写入 case，供 `search_cases.js` 复用。
